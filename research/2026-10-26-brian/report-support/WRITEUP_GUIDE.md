# Guide for Tao's own short write-up

Write the email by hand. This is an evidence checklist and suggested order, not an email draft.

1. Lead with one concrete result and a link to the independently checkable certificate. P-256284=251S+33M is five charged operations below the pinned ring289 comparator. Keep scalar-order inversion distinct from field inversion and point multiplication.
2. Explain the actual working method: a shared blackboard, many bounded search/review workers, and substantial manual coordination. Show the historical representation changes and the tools actually used. Do not describe that history as an already autonomous Apex factory.
3. Use the tool catalogue to give a small, defensible number of tool families. Separate search engines, exact evaluators/checkers, telemetry/replay, code generation and native measurement. A framework invocation, duplicate output or a proposal is a different evidence level.
4. Give two or three measured examples of what mattered. Guided selection301 versus SHA control305 is a one-seed local heuristic difference, with both worse than the291 incumbent. The P-521 history-based order lost587 to586 under equal1024-attempt budgets. A DP tie correction had zero observed state/score changes in the tested region. These are useful mixed/negative findings.
5. Mention the duplicate lesson: six file cases/four hashes were one existing285 arithmetic graph. Explain why semantic identity and live/charged counts matter more than file or worker counts.
6. If including timings, distinguish operation counts from the retained ring implementation benchmark: inversion was lower in one sampled run; signing was inconclusive. The CSV recalculation is not a fresh native benchmark.
7. End with the unfinished direction: persistent Apex memory, explicit ownership, resource-bounded tools, independent checks and durable history. The Mermaid for this is marked PROPOSED/UNFINISHED. Ask for feedback on the next experiment or integration question, not endorsement of unproved optimality or causal learning.

Suggested attachments/links: README plus the one-command verifier; one history/representation Mermaid; one budget/ablation figure; the tool/ablation table. The full matrix can remain a supporting link.

Keep separate: exact arithmetic; modular samples; a completed negative in a frozen search region; native timing; cryptographic suitability; novelty; publication/adoption/consumer acceptance. None automatically establishes the next.

Before sending, choose the claims and questions you want in your own voice. Do not feel obliged to fit the entire collection into the email.
